## Findings

### F1 — P2: apply one deadline to the entire move, including all path legs

Location: [AgentControl.cpp:1077](/C:/Users/Pengw/Documents/Codex/2026-10-13/h/outputs/Documentation-support/review-C4/sources/MMOCoreORB/src/client/agent/AgentControl.cpp:1077), introduced in `a72026b6`, expanded to 25 legs by `697f2002`.

Each leg receives the original `timeout`, and `walkPath` creates a new timer every time. Planning also takes time outside those timers. Thus a nominal 90-second move may execute many 90-second legs. The current MCP move wrapper gives the daemon **100 seconds**, after which the caller gets a timeout while the synchronous body can continue moving and keep later commands, including logout, queued.

Concrete example: two valid partial legs taking 55 seconds each both fit the per-leg 90-second allowance, but together exceed the MCP's 100-second wait. The 110-second example is timing arithmetic supported by the exact source structure, **not a wall-clock/game run**.

Fix: establish a single monotonic deadline before the first planning request; pass only remaining time to helper waits and walking; check it across frame transitions and replans; stop movement on failure. Keep the body deadline below its caller's wait allowance.

Acceptance: on a deliberately slow multi-leg route, movement stops and returns an error within the total requested deadline plus a small scheduling margin, and a following status/logout request responds promptly. Also verify a successful multi-leg route still completes.

### F2 — P2: enforce the dead/incapacitated guard on path movement

Location: [AgentControl.cpp:854](/C:/Users/Pengw/Documents/Codex/2026-10-13/h/outputs/Documentation-support/review-C4/sources/MMOCoreORB/src/client/agent/AgentControl.cpp:854) and path dispatch at line 1057, introduced by `a72026b6`.

The new dead/incapacitated check exists only in `moveTo`. With `/agentpath` available, a default `move` instead calls `walkPath`, which never checks posture. It assigns the first/frame-changing point to the local position and sends transforms even when the known posture is 13 or 14. It can continue until corrections or timeouts arrive. The server still enforces movement restrictions; **this is a missing client safety guard, not a demonstrated server bypass**.

Fix: use a shared movement-permission check before starting either route and during walking, including doorway/frame transitions. Stop and return an explicit error when death/incapacitation arrives mid-route. Do not update local coordinates or emit movement for a known immobile character.

Acceptance: with the helper enabled, issue `move` while incapacitated and while dead; both immediately fail with no outgoing movement. Repeat a live-to-incap transition during a route and verify a prompt stop. Test on the disposable galaxy; these cases were not run here.

### F3 — P2: enforce the 256-point bound inside interpolation

Location: [AgentPathCommand.h:147](/C:/Users/Pengw/Documents/Codex/2026-10-13/h/outputs/Documentation-support/review-C4/sources/MMOCoreORB/src/server/zone/objects/creature/commands/AgentPathCommand.h:147), introduced by `eebdd99d` and retained by `5c39f411`.

The outer loop checks `points.size() < 256`, but one iteration's interpolation loop can append many entries, followed by an unconditional endpoint append. The advertised reply limit therefore is not enforced, weakening the intended bound on reply size and terrain queries.

Compiled reproduction using the **unchanged reviewed expansion loop**, with synthetic paths and a zero-height terrain stub:

| Path | Destination distance | Returned points | Intended maximum |
|---|---:|---:|---:|
| (0,0) → (2048,0) | 2048 m | **257** | 256 |
| (0,0) → (1600,0) → (1600,1000) | about 1887 m | **326** | 256 |

Both destinations satisfy the helper's 2 km endpoint-distance check. These are algorithm inputs; no claim is made that Core3's pathfinder produced these exact routes in-game.

Fix: check the remaining budget before every interpolation and endpoint append. Return a valid continuous prefix and mark truncation as partial so the client can replan. Prefer RAII ownership of path results while changing this code.

Acceptance: the reproductions and a long routed test-galaxy path never return more than 256 points; the client can finish via bounded replans without jumping over the omitted section.
