## Rough overall figure and counting rule

**About 55% of a stock planet's content-system breadth is represented (18.5/34 = 54.4%, rounded).** This is an inventory estimate, not gameplay completion or a claim of half Tatooine's quest hours, objects or NPCs. Opening readiness is not averaged: one failed safety/recovery gate still blocks it.

Each numbered table row counts equally: **1** for a supplied comparable foundation; **0.5** for a limited/placeholder implementation; **0** for a missing local system. File-present but untested foundations still count here, which is why the figure must never substitute for acceptance.

- 1 point: rows **1,4,8,11,14,16,18,23,30** (9).
- 0.5 point: rows **2,3,5,6,7,9,10,13,15,17,19,20,21,22,24,25,26,31,34** (19;9.5).
- 0 point: rows **12,27,28,29,32,33** (6).
- Arithmetic: **9 + 9.5 = 18.5/34 = 54.4%**, hence **about 55%**. Bundling or splitting service rows changes the result, so retain this checklist for future comparisons.

Volume tells a different story: one city versus seven; 310 snapshot nodes versus 16,514; three habitat regions versus 58; five sites versus 11 client-listed stock POIs, with none of Hutta's sites listed yet. Scripted content and template children make snapshot-only ratios incomplete. The main shortfall is breadth across the world and profession/service loops, not an absent planet engine.

That supports Hutt autonomy and post-Krayt tensions, not automatically a copied Rebel/Imperial occupation. Do not import Canon-only Bilbousa architecture/history as Legends evidence.
