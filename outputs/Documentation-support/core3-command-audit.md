# Core3 slash commands: what has code and what does not

Generated by `tools/core3_audit/command_audit.py` (Claude, 14 Oct 2026) from `/opt/swg/Core3-dev`. Static reading of each command's `doQueueCommand()`: "implemented" means there is real code, not that it was tested in game. Owner, 14 Oct: "we may need to look at the core3 files and figure out what actually works".

**859 registered commands:** implemented 394, base-class 246, stub 159, inherits 47, todo 13.

| Status | Meaning |
|---|---|
| stub | Accepted by the server and does nothing (only the standard checks and `return SUCCESS`) |
| not-impl | Only tells the player it isn't implemented |
| base-class | Hands over to a shared engine (combat, Jedi, healing, squad leader); its numbers live in lua |
| inherits | No command code of its own; the parent class does the work |
| todo | Real code with a TODO/FIXME/"not implemented" note in the source |
| implemented | Real code |

**Read "stub" with care.** It means the slash-command handler is empty, not that the feature is missing. Many player features run through other routes: the client sends its own message packets (auctions, logout, crafting sessions), or the action runs from a radial menu or by using the object (eating, harvester controls). For player commands treat a stub as "check in game". The staff stubs are the meaningful list: those are admin tools that answer and do nothing.

## God Mode and staff commands (14 Oct finding)

- `/setGodMode <name|self> on|off` toggles the `admin` ability. A command marked admin-only is refused (`ObjectControllerImplementation.cpp`, "attempted to use ... without permissions" in the admin log) unless the player has God Mode and that command's ability. `/setGodMode` itself is not admin-only and no skill grants it; it checks for the `admin_base` skill instead.
- God Mode does **not** make you immune. `/invulnerable` does (it clears the PLAYER pvp flag, which combat treats as invulnerable); `/invulnerable invis` turns invisible.
- "todo" can still be working code: `/goto` is 197 lines with an optimisation TODO.
