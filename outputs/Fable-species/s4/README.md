# Species S4: the machinery any species needs (Chiss as the test case; nothing applied)

Fable, 14 Oct 2026. Read-only on /opt/swg (the C++ patch was built from verbatim copies of eight dev files and
proved with `git apply --check` in a scratch repository). The species package is read in memory only.

Contents: `tools/acst.py` (S4a), `cpp/species-chiss-human-rig.patch` + `work/hunks.txt` (S4b), `tools/species_tables.py`
with `stage_species()` (S4c) and its Chiss output in `staged/client/` (20 files), `out/*.json` (stage, verification and
ACST reports), `apply.sh` + `patches.tsv` (the Lua table alone, if wanted without the git patch), `checks.json`.

## S4a. asset_customization_manager.iff (FORM ACST): reader, writer, diff, splice

`tools/acst.py` follows Core3's `AssetCustomizationManagerTemplate.cpp` (twelve tables: NAME, PNOF, VNOF, DEFV, IRNG,
RTYP, UCMP, ULST, UIDX, LLST, LIDX, CIDX; CIDX maps the SOE CRC of an appearance file to a map key; a map lists its
own variables through UIDX/ULST/UCMP and the maps it inherits through LIDX/LLST). Round trips byte-identical on today's
stock copy (341,477 B, `patch_12_00.tre`) and on the package's 2016 copy (386,130 B).

What differs between 2016 and today (`out/acst-diff.json`): the 2016 copy is a later, NGE-era stock table. It carries
2,560 appearance entries today's lacks (1,044 armor and 540 cyborg pieces, 168 furniture, 90 necklaces, ARC-170 /
Jedi fighter / B-wing ship meshes, Grievous, 311 files our client does not even have, plus Gotal, Nautolan and Arcona
art), 14 palettes today's lacks (acklay/bear/minstyngar/urnsoris/uwari creature palettes, holograms, Rebel faction
armor, `npc_character_species_gotal`, `npc_skin_nautolan`, `npc_skin_arcona`, `npc_skin_ugnaught_highlights`), and 279
common appearances whose variables differ (mostly X-wing/Y-wing/A-wing/B-wing/Z-95 ship meshes and armor). Today's
copy has 40 entries the 2016 one lacks (the FX-7 medical droid and 34 NGE-only CRCs). For the species: all 18 stock
appearances the package reuses (Chiss, Bith, Hutt, Aqualish, ...) already resolve to **the same variables** in
today's table, so **Chiss needs no splice**; `gotal_m.sat` and `nautolan_m.sat` exist only in the 2016 table; `togruta_f.sat`
is in neither (Togruta would have no customization sliders, a package gap).

`splice(stock, other, appearances)` copies a map into today's table: reuses stock maps whose resolved structure is
identical, creates the rest (new keys past the last, new NAME/PNOF/VNOF/DEFV/IRNG/RTYP/UCMP entries only when
absent), keeps CIDX/UIDX/LIDX sorted for Core3's bsearch and checks the u16/u8 index limits. `verify_splice` proves every
stock appearance still resolves identically and every spliced one resolves as in the source. Tested on Gotal + Nautolan
(22 new maps, 341,867 B, round-trips): PASS. `stage_species` calls it only for appearances the base lacks.

## S4c. `species_tables.stage_species(species, stage_dir, base=None)`

For the archive builder: `stage_species(['chiss'], dir)` writes every client file the species needs, each built from
the current copy (`base(name)` -> bytes; default = the stock copy the client loads) after an exact round trip through
the writer, re-read after writing, with a report. Rows come from the package re-emitted on the base schema (the 2016
column types differ), PTMP blocks (hair, default clothing, profession defaults) are the package's forms appended to the
base form, the `ui_avatardata.inc` `<Data>` block is spliced before `</DataSource>` of `SpeciesSelection` with CRLF,
`player_species.stf` gets the package's name and **our own description** (`DESCRIPTIONS`, all 16 written) plus the
attribute block in the stock format, `skl_n`/`skl_d` get our species-skill names, `skills.iff` gets `species_<x>` cloned
from `species_human` (`SPECIES_REQUIRED` = the species), and `asset_customization_manager.iff` is spliced only when the
base lacks the species' appearances. Hair the client lacks is dropped (`hair_human_female_s33`, one row and one list
entry for Chiss). Pass `base=` your merged copies (skills.iff with the Hoth rows, the merged CRC table is not touched).

Chiss run (`out/stage-chiss-report.json`, verified by `tools/verify_staged.py`, PASS): 20 files written, 2 unchanged
(`profession_defaults_jedi.iff` has no per-species block; ACST already serves Chiss). racial_mods +1, attribute_limits +1,
customization_data +42, customization_group_instance +10, hair_assets_skill_mods +78, palette_columns +2, allow_bald +2,
seven PTMP tables +2 blocks each, ui_avatardata +1 block, player_species +2 keys, skl_n/skl_d +1, skills +1 row. Every
output round-trips, keeps every stock row/key/line, uses the stock column types, and every referenced object is in the
merged CRC table. Generalisation test (`out/stage-gotal-nautolan-test-report.json`): Gotal + Nautolan, 19 files, with
the ACST splice exercised.
